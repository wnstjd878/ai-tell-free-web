# DESIGN-COPY.md — 디자인과 카피의 바탕 규칙

> 이 문서는 프로젝트 전역 규칙(CLAUDE.md)에 두던 12절을 그대로 옮긴 것이다.
> 시각 규칙(`VISUAL-RULES.md`)과 문구 규칙(`WRITING.md`)의 상위 문서로,
> 톤을 무엇으로 정할지와 무엇을 쓰지 않을지를 정한다.

**적용 대상**: UI/프론트엔드 코드, 마케팅 카피, 그리고 **사용자나 고객이 눈으로 보는 모든 출력물** (시트/리포트/대시보드/PDF/이메일/메신저 메시지/푸시 알림 포함).

**비적용**: 일반 대화·설명 응답, 코드 식별자·변수명·함수명, 내부 로그, git commit 메시지·PR 설명, 디버그 print.

판단 기준: "이 텍스트를 비개발자가 본다 가정하고 AI 티가 나면 적용 대상." 시트 셀 안의 표 제목·라벨·해석 코멘트도 출력물이라 12.2 적용.

## 12.0 사용자 요청 우선
**다음은 이 절의 모든 규칙보다 우선한다.**
- 사용자가 레퍼런스 URL/샘플 텍스트/스크린샷을 주면 그 톤·표현·디자인을 모방.
- 사용자가 특정 라이브러리/폰트/컴포넌트를 명시 요청("shadcn 그대로 써줘", "Inter로 가자", "이 카피 그대로 써")하면 그대로 사용. 금지 리스트 적용 안 함.
- 사용자가 명시적으로 혼합 톤("모던하면서 빈티지")을 지정하면 평균화 금지 룰을 우회하고 그 의도를 따름.

## 12.1 디자인 (UI/프론트엔드)

#### 작업 순서 (최우선)
프로젝트 맥락(브랜드, 타겟, 용도)을 보고 톤 1개를 스스로 결정한 뒤 작업. 사용자에게 묻지 않음.

결정한 톤은 작업 시작 시 한 줄로 선언.
예: `톤: 에디토리얼 매거진, 90% 흑백 + 형광 옐로 액센트 10%`

톤 후보 (1개 선택, 평균화 금지):
브루탈리스트 / 에디토리얼 / 레트로퓨처(Y2K) / 럭셔리 미니멀 / 인더스트리얼 / 플레이풀 / 사이버펑크 / 스위스 모던 / 빈티지

사용자가 결과를 보고 톤이 맞지 않다고 하면 그때 다른 톤으로 재작업.

색상, 배경, 디테일은 결정된 톤에 부합하는지 기준으로 선택. 일률 규칙 없음.

#### 무조건 금지 (톤 무관 클리셰) — 12.0 예외 적용
- **폰트**: Inter, Roboto, Arial, system-ui, Geist, Space Grotesk
- **아이콘**: Lucide, Heroicons 등 라이브러리 디폴트 그대로 사용
- **레이아웃 클리셰**: 3열 카드 그리드, Hero→Feature3→CTA 무비판 적용
- **shadcn 컴포넌트 디폴트 그대로 깔기**

#### 필수
- **폰트 페어링**: 디스플레이용(헤드라인) + 본문용 2종 조합. 산세리프 한 종류로 통일하지 말 것.
  - 영문 후보: Fraunces, Instrument Serif, Bricolage Grotesque, IBM Plex, JetBrains Mono, PP Editorial
  - 한글 후보: Paperlogy, Wanted Sans, GmarketSans, 학교안심 시리즈
- **색상 시스템**: `--bg`, `--ink`, `--accent` CSS 변수로 정의. 도미넌트 1색 + 샤프한 액센트 1색 구조.
- **아이콘**: 인라인 SVG 직접 그리기 또는 이모지. 라이브러리 디폴트 사용 금지.
- **레이아웃**: 톤이 미니멀/스위스가 아니라면 비대칭, 오버랩, 그리드 깨기를 적극 활용. 판(레이아웃) 자체는 `SKELETONS.md` 의 뼈대 9종에서 고른다.
- **좌측 상단 로고/서비스명은 항상 클릭 가능 + 홈(`/`)으로 이동**: 어드민/대시보드/마케팅 랜딩 무관, 로고는 항상 `<a href="/">` 또는 동등한 클릭 핸들러를 가진 요소로.
- **날짜 입력은 데이트 피커 컴포넌트로 고정 (브라우저 기본 `<input type="date">` 금지)**: 네이티브 date 입력은 OS/브라우저마다 달력 모양이 제각각이라 매번 다르게 보임. React/Next는 `react-datepicker`를 기본으로(연/월 드롭다운 `dropdownMode="select"` + `locale="ko"` + 프로젝트 액센트 색으로 선택일 강조). value/onChange는 `"YYYY-MM-DD"` 문자열로 다루고, 공용 `DateField` 같은 래퍼 1개 만들어 전 화면에서 재사용. 다른 스택이면 그 스택의 표준 데이트 피커 위젯 사용. 사용자가 명시적으로 네이티브를 원할 때만 예외.

#### 톤별 디폴트 (참고)
- 미니멀 럭셔리 → 솔리드 화이트 OK, 무보더, 미세한 섀도우, 넓은 여백
- 브루탈리스트 → 하드 섀도우(`box-shadow: 6px 6px 0 #000`), 두꺼운 보더, 단색 강한 액센트
- Y2K/사이버펑크 → 보라/네온 그라데이션 OK, 글로우, 글래스모피즘
- 에디토리얼 → 세리프 헤드라인, 매거진 그리드, 흑백 + 1포인트 컬러
- 레트로/빈티지 → 노이즈 텍스처, 인쇄물 질감, 따뜻한 톤

#### 검수
디자인 완료 후 자체 비평 1회 실행.
"선택한 톤에 맞지 않거나 AI 디폴트로 보이는 요소 5가지를 찾아 다르게 다시 만들어라."

## 12.2 카피/텍스트 작성

#### 문장부호 금지
- em dash `—`, en dash `–` → 쉼표나 마침표로 분리. **시트/리포트 제목, 표 라벨, 해석 코멘트 전부 포함.**
- 불릿 `•` `·` `▶` → 줄바꿈 또는 번호
- 부연용 콜론(`X: Y` 형태) 남발 금지 (단 표 라벨·헤더는 허용)
- ASCII 박스 라인 `━━`, `─── `, `===` 같은 강조선 금지.

#### 시스템 코드/약어 노출 금지
- 백엔드 enum 코드(RC08, AB00 같은 상태 코드, EFI/JWT/CDN 같은 약어)를 사용자 화면에 그대로 노출 금지. 매핑 후 한글 라벨만.
- 적용: 시트/UI/PDF/대시보드 표 데이터.
- 비적용: 디버그 로그, 백엔드 API 응답, 코드 내부 dict 키.

#### 어휘 금지
- 클리셰 형용사: 혁신적인, 획기적인, 차별화된, 최적화된, 진정한
- 영어 직역체: 솔루션, 여정, 경험을 선사, ~을 제공하다
- 클리셰 패턴: "단순한 X 그 이상", "X뿐만 아니라 Y까지", "핵심은", "본질은"
- 디폴트 CTA: "지금 바로 시작하세요", "무료로 체험하기", "더 알아보기"

#### 예외 규칙
위 어휘는 **습관적/장식적 사용**만 금지. 단어 봉인이 아님.

다음 경우엔 그대로 사용.
- 기술/업계 표준 용어로 정확한 의미를 가질 때 (광고 "최적화", B2B "솔루션" 등)
- 다른 표현으로 바꾸면 의미가 흐려지거나 부정확해질 때
- 사용자가 명시적으로 그 표현을 요청하거나, 검증된 레퍼런스 카피에 들어 있을 때
- 진짜로 혁신/차별화의 사실이 있고 그걸 직설적으로 말해야 할 때

판단 기준: "이 단어를 빼면 뜻이 안 통하는가?" → 그렇다면 사용. "이 단어 없어도 뜻이 통하고, 그냥 멋있어 보이려고 넣는가?" → 그렇다면 제거.

#### 문장 패턴
- "~할 수 있습니다", "~것이 중요합니다" 한 단락에 1회만
- 같은 어미 3회 연속 금지
- 모든 섹션을 3개 항목으로 균등 분할하는 강박 금지
- 마지막에 "결론/정리하자면/한마디로" 자동 요약 단락 추가 금지
- 짧은 문장과 긴 문장을 섞어 리듬을 만든다

#### 톤 결정 우선순위
1. 사용자가 레퍼런스 샘플을 줬으면 그 톤 모방 (12.0)
2. 없으면 맥락에 맞게 1개 선택: 신문 칼럼체 / 사람의 구어체 / 단정한 평서문

#### 검수
카피 완료 후 자체 비평 1회 실행.
"AI가 쓴 것처럼 보이는 부분 7곳을 찾아 사람의 표현으로 교체하라."

#### 한국어 AI 티 제거는 im-not-ai 규칙을 쓴다 (직접 만들지 말 것)

**AI 티 나는 한국어를 잡아내거나 고칠 일이 생기면 규칙을 새로 만들지 말고 im-not-ai(https://github.com/epoko77-ai/im-not-ai) 의 `skills/humanize-korean/references/quick-rules.md` 를 읽어 쓴다.** MIT 라이선스라 가져다 써도 되고, 10개 분류 70개 패턴이 근거와 함께 정리돼 있다. 갱신은 `git pull` 만 하면 된다.

분류: A 번역투 / B 영어 인용 과다 / C 구조적 패턴 / D AI 관용구 / E 리듬 균일성 / F 과도한 수식 / G 완곡 남발 / H 접속사 남발 / I 형식명사 과다 / J 시각 장식.

자주 걸리는 것: `A-7` "가지고 있다"(→형용사), `A-8` 이중 피동, `A-18` 좌향 수식(→문장 분리), `C-8` **"A가 아니라 B" 대구 2회 초과**(사람 글 실측 0건), `C-11` 연결어미 뒤 쉼표, `D-1` "결론적으로/정리하자면", `D-3` "크게 세 가지로 나눌 수 있다" 같은 열거 도입, `H-1` 문두 접속사 5회+, `I-3` "~다는 것이다", `J-3` 대시(—) 부가 설명.

**개념을 명사로 만들어 "~이다"로 닫지 말 것.** 영어 개념을 직역한 명사(창, 자격, 판정)를 서술어 자리에 놓으면 한국말이 아니다. "뒤로 7일을 다시 세는 창이다"가 아니라 "최근 7일치만 다시 센다".

같이 쓸 것: [yoonmoon](https://github.com/amondnet/yoonmoon) 은 진단(고치지 않고 등급·의심 구간만)과 윤문이 분리돼 있어 검사 용도로 맞다. 둘 다 MIT.

**Why:** 칼럼 초안에서 AI 문장이 반복돼 규칙 8개를 손으로 만들었는데, 검색해 보니 70개짜리가 MIT로 이미 있었다. 새로 짜기 전에 이미 있는지부터 찾는다.

**How to apply:** 칼럼·블로그·보고서·알림 등 사람이 읽는 한국어를 쓰거나 검수할 때 위 파일을 열어 기준으로 삼는다. 봇이나 자동화에 붙일 땐 파일을 읽어 지시문에 싣는다(베껴 넣지 말 것. 원본이 갱신되면 어긋난다).

## 12.3 공통 원칙

- 추상 형용사("자연스럽게", "세련되게", "모던하게")는 평균값으로 수렴하므로 무시하고 구체 방향을 명시.
- "모던하면서 빈티지" 같은 형용사 평균화 금지. 한 방향으로 극단까지 민다.
  - 단, **사용자가 명시적으로 혼합 톤을 지정하면 그 의도를 따른다** (12.0).
- 작업 시작 전 톤/방향을 한 줄로 선언한 뒤 진행.
