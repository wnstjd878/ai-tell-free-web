# VISUAL-RULES.md · 첫 산출물이 "AI가 뽑은 화면"으로 안 나오게 하는 시각 규칙

목업을 그리기 **전에** 읽는다. 색·간격의 값을 정하는 변수 정의가 따로 있다면, 이 파일은 그 값을 **어디에 쓰고 어디에 쓰지 않는지**를 정한다.

AI에게 화면을 시키면 아무 지시가 없을 때 항상 같은 모양이 나온다. 크림색 배경 + 흰 카드 + 테두리 + 카드마다 왼쪽 색 세로바 + 브랜드색으로 칠한 제목 + 이모지 알약 배지. 아래 9개가 그 기본값을 끊는 규칙이다.

**이 파일은 품질만 담당한다. 화면의 인상(판·구조)은 `SKELETONS.md`의 뼈대 9종에서 고른다.** 9규칙만 지키면 밤티는 안 나지만 모든 화면이 똑같이 생기게 된다. 두 파일은 층이 다르므로 뼈대를 늘릴 때 이 규칙을 건드리지 않는다.

순서: 뼈대 고르기(`SKELETONS.html`을 브라우저로 열어서 눈으로) → 이 파일 9규칙대로 그리기 → 맨 아래 자가 점검 7개 대조.

## 요약 9줄 (프롬프트에 그대로 붙여 쓸 것)

```
- 바탕은 옅은 회색, 카드는 흰색. 테두리는 거의 안 보이는 1px까지만, 카드 안에 카드 금지
- 좌측 컬러 세로바는 화면당 1개만
- 브랜드색은 배경·제목·테두리에 쓰지 말 것. 버튼과 판정 수치에만
- 제목은 검정. 색 칠하지 말 것
- 글자 단계 6개 이상(머리말/큰제목/설명/소제목/라벨/수치)
- 라벨 왼쪽, 숫자 오른쪽 끝 정렬
- 둥근 모서리를 요소별로 다르게
- 여백 균등 금지. 8/20/40 세 단계로 묶음을 표현
- 이모지 배지 금지, 아이콘 라이브러리 기본값 그대로 금지
```

## 1. 구획은 테두리가 아니라 배경 명도로

화면을 나누는 주된 수단은 선이 아니라 바탕과 카드의 밝기 차이다. 테두리는 있어도 눈에 안 띌 만큼만 쓴다.

```
바탕        var(--bg-page)  #f6f7f9   셸 바깥
카드        var(--bg)       #ffffff   + 1px var(--line) + var(--shadow)
카드 안 묶음  var(--bg-soft)  #f7f8fa   배경만, 테두리·그림자 없음
구분선      var(--line)     #ebeef1   표의 행 사이 등
```

카드 테두리는 `--line`(#ebeef1) 딱 하나만 쓴다. 이보다 진한 회색이나 브랜드색 테두리를 두르면 화면이 격자로 잘려서 정보를 아무리 넣어도 밀도가 안 올라간다. 실제 서비스 화면에서 검증한 값이 이것이고, 여기서 더 진하게 가는 것이 AI 기본값의 증상이다.

바탕에 크림·베이지를 전면 도포하지 않는다. 바탕이 흰색에 가까우면 흰 카드가 떠 보이지 않아서 카드마다 테두리를 진하게 두르게 되고, 그 결과가 관제센터 화면이다. 순서가 반대다. 바탕을 회색으로 내리면 테두리를 안 키워도 카드가 분리된다.

**카드 안에 카드를 또 넣지 않는다.** 안쪽 묶음은 `--bg-soft` 배경만 주고 테두리와 그림자를 뺀다. 테두리 있는 상자가 두 겹 겹치는 순간 화면이 무너진다.

## 2. 좌측 컬러 세로바는 화면당 하나

카드마다 왼쪽에 굵은 색선을 다는 게 AI 기본값의 대표 증상이다. 전부 강조하면 강조가 사라진다.

한 화면에서 가장 읽혀야 하는 블록(핵심 발견, 경고) 딱 하나에만 쓴다. 배경은 `--accent-soft`, 왼쪽 선은 `--accent` 3px.

## 3. 색은 판정에만, 화면의 90%는 무채색

| 색 | 쓰는 곳 | 쓰면 안 되는 곳 |
|---|---|---|
| `--accent` #e63946 | 주 버튼, 순서 번호 원, 지금 눌러야 할 것 | 제목 글자, 카드 배경, 테두리, 사이드바 전체 |
| `--pos` #15a05a | 좋다는 판정 수치 (원가율, 증가) | 장식, 성공 문구 배경 |
| `--neg` #e0394a | 나쁘다는 판정 수치 (감소) | 일반 강조 |
| `--ink` #191f28 | 제목과 본문 **전부** | |
| `--muted` #5f6b7a | 라벨, 설명, 보조 | 본문 |

**제목에 브랜드색을 칠하지 않는다.** 제목이 검정이어야 그 아래 빨간 숫자 하나가 산다. 브랜드색을 제목·배경·테두리에 다 바르면 화면 전체가 한 톤이 되어 무엇이 중요한지 사라진다.

카테고리를 구분하려고 색을 쓰지 않는다. 색은 좋다·나쁘다·눌러라 세 가지 뜻으로만 쓴다.

## 4. 글자 단계를 6개 이상 만든다

AI 기본값은 굵은 제목과 보통 본문 두 단계뿐이라 화면이 납작하다. 최소 이만큼 벌린다.

```
머리말   11px / 700 / 자간 .08em / 대문자 / --muted     예: MENU IDEAS
큰제목   24~28px / 800 / --ink
설명     14px / 400 / --muted / 줄간격 1.6
소제목   17px / 700 / --ink
라벨     12px / 500 / --muted
수치     15~18px / 800 / --ink 또는 판정색 / tabular-nums
```

영문 소문자 머리말(overline)은 큰제목 위에 얹으면 그것만으로 에디토리얼 인상이 난다. 큰제목과 설명 사이 크기 차이는 최소 1.7배로 벌린다. 차이가 적으면 계층이 아니라 오차로 보인다.

## 5. 라벨은 왼쪽, 숫자는 오른쪽 끝

한 줄에 이름과 값이 같이 나오면 `justify-content:space-between`으로 값을 오른쪽 끝에 붙인다. 이것 하나로 나열이 표처럼 읽혀서 눈이 세로로 훑을 수 있다.

숫자에는 `font-variant-numeric: tabular-nums`를 준다(변수 정의에 이미 들어있음). 자릿수가 흔들리면 세로 비교가 안 된다.

값이 문장 안에 섞여 있으면("총 26번 언급되었습니다") 스캔이 불가능하다. 라벨과 값으로 쪼갠다.

## 6. 둥근 모서리를 요소별로 다르게

전부 같은 값이면 물렁하고 밋밋해진다. 새로 만들 때 아래 값에 맞춘다.

```
카드 .card        var(--radius)     16px
입력창 .inp                         12px
안쪽 묶음                            var(--radius-sm) 10px
배지 .badge / 칩 .chip              20~22px
버튼 .btn                           999px (완전 알약)
```

버튼을 카드와 같은 모서리로 깎지 않는다. 버튼이 알약이라 눌리는 것처럼 보이고, 카드가 각져서 담는 것처럼 보인다. 이 대비가 사라지면 화면이 통째로 물렁해진다.

## 7. 여백을 균등하게 주지 않는다

AI는 모든 간격을 24px로 깔아서 무엇이 한 묶음인지 안 보이게 만든다. 세 단계로 벌린다.

```
같은 뜻끼리 (라벨과 값, 제목과 부제)    8px
문단·항목 사이                        20px
큰 덩어리 사이 (섹션)                  40px
```

여백 차이 자체가 구획선 역할을 하므로, 이걸 지키면 1번의 "테두리 금지"가 저절로 가능해진다.

## 8. 배지·아이콘

이모지를 배지에 넣지 않는다. `✦ 자동분류 🎯 할일 💬 기록`처럼 알록달록한 알약이 나란히 붙는 순간 AI 티가 확정된다.

- 배지는 기본이 배경 없는 `--muted` 작은 글자. 한 화면에서 진짜 강조가 필요한 하나만 `--accent-soft` 채움 알약(`.badge`).
- 같은 크기 배지를 3개 넘게 나란히 놓지 않는다.
- 아이콘 라이브러리 기본값(Lucide, Heroicons)을 그대로 깔지 않는다. 인라인 SVG로 직접 그리거나, 순서는 아이콘 대신 번호 원으로 표현한다.

## 9. 세로 1열로만 쌓지 않는다

모든 블록을 위에서 아래로 같은 폭으로 쌓으면 리듬이 없다. 나란히 비교되는 것은 2열로 놓는다(원본 요약과 반응, 지표 카드). 지표 카드 줄이 그 자리다.

## 목업 완성 후 자가 점검 (1회)

1. 카드 테두리가 `--line`보다 진하거나, 바탕이 크림색이거나, 카드 안에 테두리 카드가 또 있는가 → 1번 규칙대로
2. 왼쪽 색 세로바가 두 곳 이상인가 → 하나만 남김
3. 제목에 색이 칠해져 있는가 → `--ink`로
4. 글자 크기 종류를 세어보면 3개 이하인가 → 머리말·라벨·수치를 추가
5. 숫자가 문장 안에 섞여 있는가 → 라벨과 값으로 분리, 오른쪽 정렬
6. 간격이 전부 같은 값인가 → 8/20/40으로 재배분
7. 이모지 배지나 라이브러리 기본 아이콘이 있는가 → 교체

마지막으로 한 번 더 묻는다. **"숫자와 문장을 다 지워도 화면이 똑같아 보이는가."** 똑같아 보이면 껍데기만 만든 것이다. 내용이 배치를 결정해야 한다.

## 왜 이 파일이 있나

2026-07-22, 같은 요구로 만든 두 화면을 비교한 결과를 규칙으로 옮긴 것이다. 지시 없이 뽑은 화면은 크림 바탕 + 테두리 카드 + 카드마다 왼쪽 색선 + 브랜드색 제목 + 이모지 배지로 수렴했고, 여러 번 고쳐 완성한 화면은 위 9개 규칙을 전부 만족했다. 매번 고쳐서 도달하지 말고 처음부터 이 상태로 시작한다.

`DESIGN-COPY.md`(디자인 톤 결정, 클리셰 금지)의 하위 문서다. 톤 선택(에디토리얼·브루탈리스트 등)은 그쪽에서 하고, 톤과 무관하게 항상 지키는 시각 규칙이 여기다.

## 10. 도구 표면(로그인 후 화면·어드민) 밀도 기본값

데스크탑 작업 도구를 48px 모바일 터치 규격으로 만들면 뚱뚱하고 촌스럽다(실제로 겪은 사고다). 로그인 후 화면과 어드민은 아래가 기본이고, landing(B2C 공개)만 48px 터치 규격을 유지한다.

```
본문           14.5px / 400 / 자간 -0.01em + 글자꼴 옵션 cv03·cv04·cv09·cv11·tnum
카드 제목       14.5px / 700 (800 금지, 눌러쓴 느낌)
입력칸         높이 38px / 13.5px, 예시 글자는 12px·400·연회색(#aab3bd)
버튼           34px (sm 30 / big 44) / 600
입력 라벨       12px / 600 / muted
카드           padding 20×22, radius 14
```

굵기는 화면 전체에서 최대 700.
